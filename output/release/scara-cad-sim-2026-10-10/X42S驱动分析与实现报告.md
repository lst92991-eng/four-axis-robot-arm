# X42S驱动分析与本轮实现

2026-10-10。范围是厂家资料分析、真实Linux CAN驱动源码、运动估计与软件验证。没有接管真实电机，没有刷固件、修改驱动参数、回零、使能、提交或推送。

## 已经完成什么

桌面仍为两个独立窗口：原SolidWorks机械臂三维仿真、可拖动己方棋子的YOLO棋盘。YOLO已改为宿主RTX 5060 Laptop GPU的CUDA推理，Ubuntu通过本机SSH转发调用；三维使用已开启的VMware SVGA3D。没有CPU推理回退。OpenCV仍严格为5.0.0。

已编写真正调用Linux SocketCAN的驱动，不是只打印十六进制：`simulation/x42s.cpp/.hpp`。它与仿真共用位置组包、CAN分包、应答解析和四轴速度规划。独立运动滤波在`simulation/motion_filter.cpp/.hpp`，同时供仿真和后续真实反馈使用。Ubuntu对局入口本轮仍只连接虚拟电机，不开放未标定实机动作入口。

## 转速与顺滑的真实边界

| 项目 | 手册/厂家代码确认 | 本轮处理 |
|---|---|---|
| X固件最大速度 | 3000RPM，编码单位0.1RPM | 拒绝超过协议范围；没有把演示600RPM当实机批准限值 |
| “6000RPM+” | Emm固件空载表现 | 不用于当前X方案的带负载能力估算 |
| 位置FD | 角度0.1°，加速/减速RPM/s，绝对位置标志1 | 一次规划，四轴缓存确认后统一FF66启动 |
| 平滑过渡 | 手册46页说明位置命令可打断并平滑更新 | 首版使用原生梯形曲线，不靠大量微小点反复急起急停 |
| 真正的jerk限制 | 当前FD接口没有显式jerk字段 | 当前不称为S曲线；若实测加速度转折仍激振，再增加受限S曲线及跟随验证 |
| 极限可用速度 | 还取决于负载、惯量、母线电压、动态转矩、传动和结构刚性 | 不从静态0.42N·m或宣传空载转速推断 |

旧仿真让四轴加速度相同、仅调速度，可能造成各轴加减速阶段不一致。本轮改为速度、加速度都按各轴电机位移缩放。连续理想模型下，各轴共享归一化进度；协议0.1RPM/1RPM/s量化及真实跟随误差仍会产生偏差，不能说同步启动就是路径绝对同步。CAD采样约束仍在规划和每个虚拟采样中检查。

肩轴减速比50由用户确认：600RPM电机转速对应输出72°/s，3000RPM对应360°/s；这是换算，不是可靠运行速度。Z暂假设导程4mm/转，600RPM才对应40mm/s；导程确认前不能用于实机。

梯形曲线消除了直接跳目标速度，却仍有加速度转折。EKF估计状态，不能代替轨迹规划，也不能让齿隙、松动和柔性凭空消失。

## 真实驱动的执行顺序

1. 打开现有SocketCAN接口，不自动设置波特率、刷CANable、使能或回零。
2. 有界清掉旧接收帧，逐节点读取1A、1F、16、3A、36，核验固件/模式、心跳、使能及位置。
3. 将已标定上层提供的四个**电机轴绝对角度**转换为FD报文，分成两包发送。
4. 四轴均收到`FD 02 6B`后，发送广播`FF 66 6B`。缺少任一确认就停止，不启动部分轴。
5. 以20ms为期望周期查询36位置、35速度、3A状态。时间戳是主机收到反馈的时刻，不是假装驱动带硬件采样时间戳。
6. 位置、速度、状态连续三轮满足才返回成功：当前电机侧容差0.2°、0.5RPM；它们是初始软件阈值，非整机精度验收值。单独9F不算稳定到位。
7. 堵转/拒绝/应答过期/到位超时/接口错误时，逐节点发`FE 98 00 6B`，不自动清故障或续跑，不自动失能Z轴。

每个应答等待上限200ms，成组反馈新鲜度上限100ms，总到位时间上限为规划时间加1s。控制回调获得实际经过时间，不能用假定20ms掩盖调度延迟。

20ms内四节点各查询三项，需要12个请求和12个应答；500kbit/s下按实际帧长估算约23%总线占用，填充和其他流量另计。没有开启1ms定时上报或同时开两套反馈来源。当前版本不能代替实机总线负载测试。

软件无法在USB/CAN断线后保证FE到达。驱动心跳保护默认0，本实现要求读取值为100～1000ms，建议先验证500ms；不自动修改持久参数。心跳的失联停机和独立停止措施仍须在实机阶段验证，不能由“已发停止”推断“机械臂已停”。

## EKF到底使用什么

状态`[肩角, 肘角, 肩角速度, 肘角速度]`，角度rad，角速度rad/s。20ms匀速预测包含加速度过程噪声；当前噪声参数为假设，等待辨识。

编码器测量是减速器输入侧电机角度，经速比/方向/零点换算。仅有这组线性测量时，程序明确执行KF。只有传入独立末端XY测量时才加入非线性FK及雅可比，成为EKF；超过100ms、非有限值或归一化残差过大的XY不参与修正。Joseph协方差更新和线性方程求解保留数值稳定。

仿真里XY仍来自合成传感器；YOLO目前识别棋子，尚未实现末端运动中的连续视觉跟踪。真实接机不能把`fk(encoder)`当成独立XY再喂回滤波器，也不能用命令目标代替测量。仅靠输入侧编码器无法观测输出背隙：若要补偿这一部分，必须有真实负载侧编码器或可靠末端观测。

滤波回调可以接入真实四轴反馈，但默认真实驱动不根据未验证的视觉值自动追加补偿运动。仿真的有限位置修正不自动获得实机授权。

## 验证与复现

已在Ubuntu RV虚拟机编译；真实SocketCAN代码通过隔离网络命名空间中的vcan。该测试的假电机专门验证报文/应答顺序与异常，反馈位置简化为立即到目标；它不证明真实动态响应。三维仿真的滞后、背隙、编码器噪声仍由原虚拟电机模型独立验证。

```sh
cd /home/st/scara-sim
cmake -S . -B build -DSIM_DRIVER_CHECKS=ON \
  -DOpenCV_DIR="$PWD/deps-opencv-5.0.0/lib/cmake/opencv5"
cmake --build build -j4
unshare -Urn sh -c 'ip link add vcan0 type vcan; ip link set vcan0 up; \
  LD_LIBRARY_PATH=/home/st/scara-sim/deps-opencv-5.0.0/lib \
  /home/st/scara-sim/build/driver_check vcan0'
```

覆盖正常四轴动作、缺少ACK不启动、E2拒绝、堵转、反馈丢失、9F/到位状态虚假但位置未到、Emm模式拒绝、心跳未启用拒绝，以及畸形应答/超速参数、KF/EKF切换、XY过期/异常值。通过条件记录在`output/driver-check.log`，不操作真实接口。

CAN和运动滤波已用项目固定Luckfox Cortex-A7/uClibc工具链交叉编译链接为ARM EABI5库，依赖OpenCV5的`libopencv_core.so.500`。复现脚本`simulation/build-motion-rv1106.sh`。交叉编译不等于板上收发通过。

历史板端记录Linux5.10.160未启用CONFIG_CAN；RV1106接入仍需复核当前内核的CAN、CAN_RAW、CAN_DEV、USB_GS_USB及USB Host。这些驱动条件缺失时，C++代码不能替代内核支持；不因此自动重刷整个系统。

四个共享驱动/滤波文件共401物理行、387有效行（排除空行和独立注释行），落在本轮500有效行预算内。滤波有一部分从主文件移出，401不能视作项目净增；主文件当前835物理行。精确计数见`output/simulation-review/source-size.json`，测试、厂家源码、图形库、模型和构建输出单独排除。没有再加CANopen、ROS、电机插件框架或另一套棋局。
