# SCARA 中国象棋教学项目

C++17 + **OpenCV 5.0.0**，RV1106/MIS5001 MIPI 摄像头，YOLOv5s/ReLU 的 RKNN INT8 模型，Pikafish，虚拟四轴 SCARA。当前交付完成软件对局和虚拟取放闭环；电机驱动资料后续提供，本版不会发送真实电机命令。

## 先运行，再读代码

已验证的板端运行包位于 `output/rv1106/scara-robot/`，入口只有 `run-robot.sh`。包内包含主程序、OpenCV 5 库、象棋模型、Pikafish 与解压后的 NNUE。

在 Windows PowerShell、项目根目录执行：

```powershell
# 先用 adb devices 查看序列号，再填入 -Serial。
.\tools\deploy-robot.ps1 -Serial 759dce9b268fd05e
```

在板端登录终端执行：

```sh
sh /root/scara-robot/run-robot.sh
```

主程序从标准输入接收命令，标准输出是给界面使用的 JSON。可依次输入 `move e3e4`、`demo 3`、`pause`、`new`、`scan`、`resign`、`draw`、`quit`。人执红、机器执黑，从标准开局开始。`pause` 保留中途场景，`new` 重建虚拟场景；这两个命令都不是实体机械臂的回零指令。

使用图形界面时，不要同时在终端启动另一份主程序：

1. 将 `tools/robot-viewer/connection.example.json` 复制为同目录的 `connection.json`，填写已经验证能登录板子的 SSH 命令。先在终端确认 SSH 登录成功。
2. 在电脑或 Ubuntu 运行 `python tools/robot-viewer/server.py`。
3. 浏览器打开 `http://127.0.0.1:8767/`。点红子、再点绿色落点；也可以点“演示 3 回合”。
4. 结束时在运行 Python 的终端按 Ctrl-C，关闭服务及其主程序。只关闭网页不会结束服务。

例如，使用已配置的 SSH 主机名 `rv1106`：

```json
{
  "argv": ["ssh", "-T", "-o", "BatchMode=yes", "-o", "ConnectTimeout=5",
           "-o", "ServerAliveInterval=3", "-o", "ServerAliveCountMax=2",
           "rv1106", "sh /root/scara-robot/run-robot.sh"]
}
```

界面左侧是已确认棋局，右侧是虚拟机械臂和它实际搬动后的场景。取放中棋子会离开棋盘、挂在末端，再被释放；吃子先移走目标棋子。每次摄像识别结束，下面显示最近采集图、角标及透视校正结果；定位失败时校正图为空。页面只监听本机地址。

## 一次落子如何完成

```text
MIPI NV12 → OpenCV BGR → 四个 ArUco → EKF平滑映射 → 透视校正
         → RGB / YOLOv5s NPU → 红黑14类 → 9×10棋局 → 连续3帧一致
         → 与当前棋局比较 → Pikafish合法走法 → 确认人的走法
         → Pikafish计算应手 → 运动规划/FK/IK → 虚拟取放
         → 检查实际模拟盘面 → 提交机器走法 → 下一回合
```

虚拟输入用于没有棋具时完成整局软件演示。点击走法也必须经过真实 Pikafish 的合法性检查。相机输入用于确认实物盘面的变化；当前执行器仍是虚拟机械臂，所以相机模式下机器应手之后，需要人手把实物盘面同步到界面再走下一着。更换实体驱动后，这一步由真实取放和再次拍照完成。

RV1106 内存有限：相机/NPU处理完成并释放后，才启动 Pikafish；引擎计算完立即退出。界面 Python 运行在电脑上，只转发命令与显示状态，不运行另一套棋规或检测模型。

## 代码按这个顺序读

| 文件 | 职责 |
|---|---|
| `main.cpp` | 依次处理命令、观察、棋力计算、运动、执行确认；唯一业务入口 |
| `app/config.hpp` | 棋盘几何、类别顺序、虚拟运动参数 |
| `vision/camera.cpp` | MIS5001采集、帧管道、NV12转BGR、取消与回收 |
| `vision/board_vision.cpp` | 四角定位、EKF、透视变换、检测框整理成90交点 |
| `vision/detector.cpp` | RKNN加载、RGB letterbox、NPU、INT8后处理/NMS |
| `chess/board.cpp` | FEN、观察匹配、待执行走法、提交、结果与历史 |
| `chess/pikafish.cpp` | 单个引擎进程的UCI通信、合法走法、应手、超时取消 |
| `algorithm/fk.cpp`、`ik.cpp` | 四轴正逆运动学，毫米/弧度 |
| `algorithm/homography_ekf.cpp` | 8个单应参数的扩展卡尔曼滤波 |
| `algorithm/motion_plan.cpp` | 连续逆解、限位/速度检查、取放步骤 |
| `robot/simulator.cpp` | 按时间推进关节、吸取/释放、独立模拟盘面 |
| `app/commands.hpp` | 有界输入；暂停、新局、退出优先 |

每个模块都是普通函数或具体对象，没有插件框架、继承树、任务总线。`tests/main.cpp` 是统一测试入口。旧的 `vision/main.cpp` 只保留“格式转换”第一课，不参与完整程序构建。旧五子棋打印稿和旧引擎查看器属于历史资料，不应与本版混用。

## 算法的实际含义

- FK/IK 使用 SolidWorks 得到的两段臂长 **195 / 275 mm**；末端工具与第四轴同轴。理想几何可达范围为半径80～470mm。Z是末端高度，不是尚未知的电机脉冲数。
- EKF状态为归一化单应矩阵的8个参数，测量是4个标记的16个角点。测量方程包含透视除法，使用解析雅可比、马氏距离剔除与Joseph协方差更新。它减少棋盘映射抖动；没有冒充编码器闭环。
- 运动规划明确列出安全高度、下降、吸取、抬起、平移、下降、释放、抬起。连续选解并检查关节限位、速度和穿越内部不可达区域。它没有实体碰撞模型或加速度规划；当前限位/速度参数均为虚拟假设，`calibrated=false`。
- 模拟器在吸盘事件发生时才改变世界棋子；机器应手只有在运动成功且观察与预期一致后才写入历史。停止时保留中间场景和吸盘状态，不能把未执行完的走法算作成功。

## 棋盘与棋具

选择**直径35mm**作为教学基准。这是市售常见规格之一，例如[得力9566](https://www.deliworld.com/product/educational-toy/)；同系列还有40/50mm，并不存在所有厂家统一的“最常见尺寸”。实际购买后先测量，再修改 `app/config.hpp` 并重新生成打印稿。

- 正式打印稿：`output/pdf/xiangqi-board-a4-tiles.pdf`（6页A4），或 `xiangqi-board-a1.pdf`（一张A1）。
- 外板480×520mm，格距40mm，9列10行；标记黑框48mm，完整白边8mm，ID顺序0左上、1右上、2右下、3左下。
- A4按 `1 2 3 / 4 5 6` 排列。选择**100%实际大小**，先量每页100mm标尺；横向重叠30mm、纵向20mm，对齐重复网格，从背面固定。不能缩印成一张A4，也不要剪掉标记白边。
- 使用平整哑光底板，固定相机，让整张棋盘和四角完整入镜。文字必须清晰，避免强反光。原来的五子棋纸子没有象棋身份，不能用于此模型。
- `assets/xiangqi/generate_board.py` 从同一份 `app/config.hpp` 读取尺寸。重建需要 ReportLab 和中文TrueType字体：Windows默认微软雅黑，其他系统把字体路径作为唯一参数传入。OpenCV5用于标记识别验证；校验记录在同目录。

## 模型与可替换位置

当前模型是 **YOLOv5s/ReLU，640×640，14类，RKNN INT8**，类别顺序 `kabnrcpKABNRCP`：黑将士象马车炮卒，红帅仕相马车炮兵。模型输出采用固定三头和anchors；换模型需要同时核验类别、输出形状、量化参数和anchors，不能仅替换文件名。

训练使用218张真实照片、2694框。原始资料是7种棋子类型，本项目依据墨色派生红黑14类并视觉核对。按原图/近重复组隔离为174/22/22张，最后22张仅用于独立测试。部署阈值0.50、跨类别NMS IoU0.45；量化校准只使用训练集。

固定权重、数据、来源/许可、导出输入和SHA-256在交付包的 `model-training/`；训练/导出操作见 `tools/model/SOURCES.md`，逐图评估见 `tools/model/validation.json`。当前测试结果不能替代你将购买的棋具和机位实拍验收。训练和主程序均使用OpenCV5；RKNN1.6的隔离离线转换环境依赖旧版Python OpenCV，不进入板端或预览运行环境。

| 要替换什么 | 改哪里 |
|---|---|
| 棋盘尺寸、摆放、吃子槽 | `app/config.hpp`，重新生成板面、标定与可达性检查 |
| 不同摄像头/取帧接口 | `vision/camera.cpp`，向上仍交付BGR Mat |
| 已训练的同协议象棋模型 | `config/robot.json` 的model_path；按上面核验输出约定 |
| 棋力、运行路径、仿真速度 | `config/robot.json` |
| 真实电机/驱动板 | 以 `robot/simulator.cpp` 的执行边界接入驱动，保留main的待执行/复核/提交顺序 |

接真实驱动时还必须补齐电机零点、减速比、丝杆导程、限位、回零、急停、加速度、工具高度、碰撞及反馈。用实际拍照结果替换 `virtualObservation(arm.board())`；不得把发送命令成功当作落子成功。这些资料尚未提供，本版明确用虚拟执行器交付。

## 棋规与验收边界

基本走法、自将检查由固定Pikafish的合法走法列表裁定；FEN和完整历史都送入引擎。无合法走法即判当前方负，包含中国象棋的将死和困毙；支持认输、双方约定和棋。三次重复转“待裁定”，没有用三次重复自动判和，更没有声称实现完整长将/长捉竞赛裁判。

已完成：

- RV1106真实NPU测试：独立22张/277框，以类别一致且IoU≥0.50一对一匹配，TP277、FP0、FN0；完整检测平均85.31ms。该耗时不含摄像采集/图像传输。
- 真实MIS5001采集、OpenCV5转换与四角缺失拒绝；当前现场画面没有可用象棋盘，未宣称实物整盘识别通过。
- RV1106实际Pikafish与虚拟机械臂连续对弈、吃子、途中带子暂停、取消思考/采集、非法走法不改棋局、认输/和棋。结果在 `output/rv1106/full-validation/`。
- 统一测试覆盖FK/IK、EKF、规划、棋局提交、模拟执行、输入控制、OpenCV5角标与透视。板端和Ubuntu分别构建验证。

从源码构建、固定依赖与部署参数见 `tools/BUILD.md`。运行包自带SHA-256清单；源码、运行包、模型/数据分别记录哈希。哈希一致只证明文件一致，不能代替实机、识别精度或实体运动验收。

## 建议的教学顺序

1. `vision/main.cpp`：一帧NV12 → BGR → 保存；先理解Mat和通道。
2. 四角标记 → 坐标 → 透视变换，再读EKF为何使用非线性测量。
3. 用固定模型看检测框、类别、90交点，理解不确定盘面为何不提交。
4. FEN/走法/合法性 → 引擎计算 → 完整对局历史。
5. FK/IK → 一次取放 → 吃子 → 暂停与复核。
6. 回到 `main.cpp` 顺序走读整条链，最后再用已提供的硬件资料替换模拟器。
