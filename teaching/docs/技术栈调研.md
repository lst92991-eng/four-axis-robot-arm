# 技术栈与开源实现初步调研

日期：2026-10-14。本文记录项目已选技术路线及采用理由，不将上游最新版本自动替换为本板依赖。

## 1. 技术路线

| 部分 | 选用方案 | 理由与适用边界 |
|---|---|---|
| 主控/语言 | RV1106 Linux、C++17 | 沿用已有板卡与板端运行经验；协议、图像、引擎与业务统一用C++表达 |
| 工具链 | 项目固定Cortex-A7/uClibc GCC8.3，hard-float/NEON | 与现有RV1106 ABI匹配；普通Ubuntu交叉编译器不直接替代 |
| 电机通信 | Linux SocketCAN，CANable/candleLight，经典CAN扩展帧 | 使用内核统一收发接口；电机节点/协议放在Motor层 |
| 电机协议 | 当前已实测的张大头Emm子集 | 复用节点1验证结果，逐项补定位等所需命令，不全量搬入配置/校准功能 |
| 图像处理 | OpenCV 5.0.0 | 项目固定版本；负责NV12转换、ArUco、透视/标定、图像准备及绘制 |
| 棋子识别 | YOLOv5＋RKNN/NPU | 识别红黑14类；先评估现有权重对实际棋具的效果，再决定补数据/训练 |
| 棋力 | Pikafish，UCI进程通信 | 复用现有中国象棋引擎，不另写搜索器；板端版本与NNUE沿用已验组合 |
| 算法 | FK/IK、必要轨迹、运动KF/EKF | 算法必须服务实际坐标/反馈；仅编码器线性模型称KF，独立非线性末端观测参与才称EKF |

运行顺序：MIPI NV12 → OpenCV处理/定位 → RKNN推理 → 90交点盘面 → 棋局/Pikafish → 运动与取放 → 停车复拍 → 确认提交。

RKNN转换工具在电脑端生成模型，板端使用C/C++ Runtime运行；官方列有RV1106支持。版本仍须和本板运行库匹配，不能仅凭芯片在支持列表中就认定现有模型可用。[Rockchip官方仓库](https://github.com/airockchip/rknn-toolkit2)

OpenCV和YOLO分担几何处理与身份识别；Pikafish是UCI中国象棋引擎。功能与接口参考：[OpenCV官方文档](https://docs.opencv.org/5.0/)、[YOLOv5官方仓库](https://github.com/ultralytics/yolov5)、[Pikafish官方仓库](https://github.com/official-pikafish/Pikafish)。具体模型/引擎版本及许可证随实际引入记录，本次不下载或更换依赖。

## 2. CAN与电机相关开源经验

| 一手来源 | 核对到的设计 | 本项目吸收与舍弃 |
|---|---|---|
| [SocketCAN内核文档](https://www.kernel.org/doc/html/latest/networking/can.html) | socket创建、接口绑定、read/write；错误帧默认不接收，需显式订阅 | 直接使用系统API；保留实际错误可见性，不自建通用硬件框架 |
| [can-utils/cansend.c](https://github.com/linux-can/can-utils/blob/master/cansend.c) | if_nametoindex查询接口，系统操作分别判断；还处理CAN FD/XL和命令行帧解析 | 借鉴名称查询与顺序执行；只实现当前经典CAN收发，不搬入FD/XL或只发不收配置 |
| [ODrive多电机接口说明](https://github.com/odriverobotics/ros_odrive/blob/main/odrive_ros2_control/README.md) | 总线接口名与各关节node_id分开，使用SocketCAN；错误反馈仍有待办 | 借鉴总线/节点职责边界，不引入ROS2插件，也不套用ODrive报文 |
| [第三方ZDT EmmV5库](https://github.com/RyanZhangK/ZDT_EmmV5_Driver) | STM32 HAL串口传输与电机指令分文件 | 可参考传输/协议划分；不是Linux CAN库或厂家权威参数来源，不能照搬速度范围和单位 |

这些来源是设计参考，不是可直接替代本机测试的证据。使用系统API独立编写最小代码；若后续复制开源实现，记录具体版本并保留适用许可证。

## 3. 第一个接口的设计依据

用户已认可`Can::Can(const char* interface)`的候选设计：

- 以`can0`等接口名初始化，`if_nametoindex()`直接取得接口编号。
- 教学调用保证正确名称，不额外增加名称判空/长度检查。
- 创建非阻塞CAN socket，绑定接口，再订阅CAN错误。
- 各个系统操作分别检查失败；绑定或订阅失败时关闭句柄并抛出异常。
- 不使用require封装或整层try/catch；代码按执行顺序直接展开。
- 构造不发送电机帧；波特率和接口启用由板端配置负责。

接口编号查询失败返回0，而SocketCAN把编号0解释为所有CAN接口，所以仍检查系统查询结果。该语义见上述内核文档。析构、发送、接收及Motor方法另行逐个商定，本次文档提交不包含这些代码。
