# SCARA 四轴下棋教学项目开源方案调研

日期：2026-10-08。首个聊天：`01-需求调研与技术选型-2026-10-08`。

**建议先做一个几千行规模、职责清楚的五子棋机器人：保留已有四轴机械结构，棋局与视觉在上层，机械坐标、取放和电机执行在下层。兼容后续棋类靠几个稳定的函数边界实现。首版不需要 ROS、MoveIt、深度学习训练、Web 服务或插件框架。** 这是针对本项目教学目标的设计建议，具体主控和上位机技术栈还需与现有电控对应。

最值得先读的资料是 TooAboil 的 SCARA 五子棋主链、Raspberry-Chess 的小型对弈应用，以及 Pybot/Marcel 的紧凑运动控制。它们分别展示了业务顺序、视觉与棋局分工、板端控制规模，但都不能直接视为适配本机的完整交付基线。

**项目约束**

- 首个棋类是五子棋，后续保留扩展棋类的能力。
- 用于教学：代码量尽量小，语法简单，流程可顺着读懂；不能通过压缩表达式、去掉注释或省略故障处理来缩行。
- 用户于 2026-10-08 明确以 C++17 为主要开发标准，并接受使用新版 OpenCV。视觉程序按 **OpenCV 5.0.0 + C++17** 选型，后续固定具体依赖版本；这不表示已经完成安装、编译或硬件验证。
- 用户明确硬件已确定，并提供尚硅谷四轴机械结构压缩包；软件调研以该硬件为前提。
- 当前项目 `main.cpp` 与 `algorithm` 中共 11 个 C++ 源/头文件为空，Git 尚无提交；本次没有改写这些文件。
- RV1106/boomPI 的服务端黑箱和教材冻结约定是另一个项目的专属范围，本次不自动套用到 SCARA。

**调研覆盖与计量口径**

本次覆盖 SCARA 五子棋、其他机构五子棋、井字棋、国际象棋、中国象棋、围棋，以及 SCARA 固件平台、规则库与棋力引擎。检索 GitHub、公开技术教程、Gitee 线索与中英文搜索，逐步回到作者仓库验证。当前形成的是广覆盖候选和代表源码实测，不能承诺穷尽互联网全部类似项目；未公开、已删除、没有索引或仅提供演示的项目无法完整计量。

下表的行数统一写成 **物理行 / 非空行**，两者都包含注释。它们衡量源码阅读量，不是去注释 SLOC，也不是运行内存或编译后固件大小。文件范围必须一起读：应用、完整固件、第三方库、生成文件、训练脚本分别列出，不能混在一起排名。

排除 Git 元数据、构建输出、图片、CAD、模型权重、音频、可执行文件、文档等；配置和包管理文件不在源码行数内，但仍属于部署成本。Notebook 只统计 code cell。外部 SDK、HAL、Arduino 核心、ROS、OpenCV、深度学习框架不会因为未计入应用行数就消失。所有样本只做了静态检查，没有运行第三方代码或进行真机复现。

具体 SHA、文件清单和统计脚本保存在四份分报告及相邻 JSON 中。调研样本固定版本不等于用户项目冻结版本。GitHub 星数、仓库磁盘大小和主语言占比不作为教学规模判据。

**面向本项目的最小结构建议**

保留三层阅读顺序：应用回合流程 → 棋局/视觉/取放业务 → 硬件和通信。先用普通函数、结构体、枚举和一个可读的状态机；没有第二个真实实现时，不建立接口继承树、工厂、插件注册或消息总线。

| 职责 | 首版应做什么 | 后续棋类变化时是否改动 |
| --- | --- | --- |
| 应用流程 | 等人走棋、确认观测、选点、执行、复核、交接回合、故障停止 | 改少量回合规则，不重写驱动 |
| 棋局与决策 | 行列、颜色、合法落子、胜负；启发式评分，必要时浅层 αβ | 新棋类新增自己的规则与决策，出现第二种后再提取共同部分 |
| 视觉 | 输出观测棋盘和可信/不确定状态；固定相机、固定棋盘、稳定光照下先用传统图像处理 | 棋子类别/棋盘布局可能变化；不能承诺只改棋盘大小 |
| 坐标与标定 | 棋盘行列→平面位置→机器人坐标，统一毫米/弧度或度的约定 | 更换棋盘参数，保留运动代码 |
| 取放与运动 | 来源→目的搬运；抬起、移动、下降、取放；逆解、加减速、运动范围、完成反馈 | 棋类负责组合多次搬运，底层不需要知道“活三”“将军” |
| 驱动/通信 | 定时器/步进或既有总线驱动，末端控制，少量命令与状态反馈 | 棋类扩展通常不变 |

首版主线可直接读成：**等待人手离开/确认按钮 → 稳定识别 → 判断是否出现合法一步 → 更新已确认人类着法 → 选择机器人着法 → 搬棋子 → 确认动作和盘面 → 更新已确认机器人着法。** 视觉结果与已确认棋局分开；发送成功不等于棋子已放到位。通信重试不能盲目重复整次搬运。

五子棋建议先明确采用 15×15 无禁手自由规则，并以“连成至少五子”为胜；这是待确认的首版范围建议，不冒称已支持连珠竞赛规则。先保证必胜点、必挡点和合法落子，再评估搜索深度，不把训练模型作为前置条件。调试首版可先通过手工输入落点打通动作，再接视觉，最终目标仍是完整人机对弈。

视觉程序采用 **OpenCV 5.0.0 + C++17**，具体运行于 PC 或嵌入式 Linux 平台，仍随现有电控和摄像头方案确认。用户已经使用 C++17，不再因兼容旧语言标准而优先选择 OpenCV 4.x。[OpenCV 5.0.0 官方发布](https://github.com/opencv/opencv/releases/tag/5.0.0)、[官方迁移说明](https://github.com/opencv/opencv/wiki/OpenCV-4-to-5-migration)。Qt Widgets 只在确实需要可视标定/棋盘界面时引入；初期不叠加 Web 前后端。MCU 的语言与工具链随控制板确认，RTOS 是否必要取决于真实并发要求。

采用 C++17 后仍优先用普通函数、结构体、枚举、标准容器和明确的资源生命周期表达业务；不为了使用新标准而增加模板技巧或多层抽象。固定相机、人工四点标定、棋盘拉正、网格区域识别及多帧稳定确认，仍以 **250～450 物理行（含必要注释与空行）**作为视觉模块估算；不含 OpenCV 本身、五子棋 AI、自动找棋盘或运动控制，也尚未实测。

OpenCV 5.0.0 的接口组织需按对应版本编写：`getPerspectiveTransform()` 在 `geometry` 模块（`opencv2/geometry/2d.hpp`），`warpPerspective()` 在 `imgproc` 模块；前述两个核心调用方式仍适用。其他直接使用模块为 `core`、`videoio` 和调试用的 `highgui`，读写图片时加 `imgcodecs`；编译时还需包含模块声明的依赖。无需为这条基础视觉路径引入 contrib 或神经网络。[5.0.0 几何接口源码](https://github.com/opencv/opencv/blob/5.0.0/modules/geometry/include/opencv2/geometry/2d.hpp)、[5.0.0 图像处理接口源码](https://github.com/opencv/opencv/blob/5.0.0/modules/imgproc/include/opencv2/imgproc.hpp)。

**兼容其他棋类的边界**

不把棋盘的 `row,col` 直接当电机驱动协议；底层接受明确的机械目标和取放控制。棋盘坐标映射与机械参数独立保存。当前只实现实际使用的取放流程，未来新增棋类时再增加组合方式。

| 扩展棋类 | 可复用 | 新增的实际要求 |
| --- | --- | --- |
| 井字棋 | 识别空/黑/白、供子→落点、坐标映射 | 小棋盘与新胜负/决策，成本最低 |
| 围棋 | 圆片抓取、平面落点、视觉基础 | 一步可能提多子、气/劫/禁入点、停着、终局计分；不能只把 15 改为 19 |
| 中国象棋 | 平面取放、坐标标定、电机驱动 | 棋子身份或已知开局与合法着法推断；起点→终点；吃子先送弃子区 |
| 国际象棋 | 移动和吃子动作基础 | 立体高度/夹取差异、易位双搬运、吃过路兵移除非目标格、升变备用棋子或人工确认 |
| 黑白棋 | 部分棋盘识别与平面搬运 | 翻面能力；标准四轴仅绕竖直轴旋转不等于能翻棋子，需要额外机构或人工步骤 |

这里最值得现在做的兼容是：**规则不依赖毫米，运动不依赖棋类，一步棋允许将来对应多次搬运。** 不预建通用动作解释器，不先实现全部特殊规则，也不承诺机械结构能支持所有棋类。

**代码预算建议**

预算是本项目的设计约束建议，不是现成开源项目的测量结果或交付承诺。硬件接口未核对前只能先给范围。

- 若已有可靠电机驱动/控制器可用，首版自有源码可先以 **2,500～4,500 非空行（含必要注释）**、约 **12～20 个源/头文件** 为评审目标，覆盖规则、基础决策、视觉标定、取放、回合管理和必要异常路径。
- 若还要从定时器开始实现四轴脉冲同步、加减速、归零和通信，另评估约 **1,000～2,000 非空行**；避免将这部分隐藏在“只需几百行”的承诺里。实际工作量由驱动和硬件反馈方式决定。
- HAL/CMSIS、OpenCV、GUI 库等单列依赖与版本。学生必读/必写的代码，生成代码，第三方库，配置与资源分别统计。
- 单文件约 500～600 物理行时检查是否职责过多；不是达到数字就机械拆分。首版一个入口、一份配置、一条真实执行路径。
- 简化的优先级：先删非必需 UI、云服务、语音、棋谱、仿真、训练，再减少抽象；保留不可达检查、关节限位、路径安全、回零超时、停止、失联响应与完成确认。

**已收到硬件资料后的判断**

压缩包含总装、零件、加工图、STEP 和机械物料表，未含控制源码或电控说明。本轮已读取目录和 BOM，未在 SolidWorks 内求解装配，因此没有宣布确定臂长、第四轴传动或棋盘覆盖率。物料表的 250/330 是零件包络长度，不能直接当转轴中心距；500 mm 丝杆也不是 500 mm 有效行程。具体来源和单元格见 [硬件输入记录](hardware-input-notes.md)。

下一步应在现有硬件上核对：主控/上位机、电机驱动接口、回零/限位、末端工具、摄像头，以及装配的关节中心、正方向、传动耦合和可用行程。确定这些后，才适合固定开发栈、运动参数和课程代码预算。本轮调研可以先确定软件职责，无需等待这些参数才能形成结论。
