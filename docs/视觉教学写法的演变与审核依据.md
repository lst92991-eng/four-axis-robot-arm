## 三个能指导下一次改代码的实例

**1. 先让学生能写完一帧。** 早期入口要同时理解 `stopped`、`limit`、`count`，还得解释临时 JPEG 和 `rename`。改到 `871cd2d` 时，学生在同一个 `while (running)` 里看见数据的名字、含义和去向。下面摘的是当时五行核心调用，完整函数另有预览输出和退出收尾。[早期入口](https://github.com/lst92991-eng/four-axis-robot-arm/blob/e86f26fd0462e53a67d22a40a6d69992a7656477/app/vision_main.cpp) · [获认可的入口](https://github.com/lst92991-eng/four-axis-robot-arm/blob/871cd2d7ea21f89eeccd59f7f3c12d4b486b8b00/app/vision_main.cpp)

```cpp
Camera_read(source);
Vision_prepare(source, input);
Yolo_run(input, heads);
Vision_decode(heads, pieces);
Vision_draw(source, pieces, labels, preview);
```

这里的 `heads` 是 NPU 三路原始输出，`pieces` 才是带类别、分数和原图位置的棋子列表。分成两步有一个明确收益：老师可以在两行之间停下来解释“模型输出怎样变成棋子”。预览保存只消费画好的图。

**2. 改到被指出的函数体。** `1c59289` 重排了相机说明，但读帧失败仍会跳出，你当场指出执行方式没有改。到 `6e1512a`，临时读失败会回到 `while (capturing)` 重试，却又增加了一套消费者五秒超时。你再次追问后，`3f8aa57` 删除这套截止时间和循环内重复的停止判断，`2ce033d` 把打开相机写成“收尾旧连接 → 把打开结果赋给接收开关 → 启动接收线程”。当时 FFmpeg 单次读写等待有自己的用途。后来课堂入口固定到本机 V4L2 同步取帧，才连同后台线程、锁、通知和最新帧缓存一起省去。[收到纠正前](https://github.com/lst92991-eng/four-axis-robot-arm/blob/1c59289c0ff2fa2ab5a5ef48170831d754197079/vision/capture.cpp) · [删除应用层超时](https://github.com/lst92991-eng/four-axis-robot-arm/blob/3f8aa5781cbf49d5c05944bb102007f19d6f14b3/vision/capture.cpp) · [当时的打开顺序](https://github.com/lst92991-eng/four-axis-robot-arm/blob/2ce033d2d7aea0d1c9c5c0bf8d07a81ac204363f/vision/capture.cpp) · [现用同步取帧](../vision/capture.cpp)

**3. 留下解释物理数据所需的步骤。** YOLO 的候选框、重复框筛选、原图坐标各回答一个实际问题。`5d4c31b` 把三者按数据顺序放在解码函数里，每个中间结果都有下一位使用者。对 RKNN，同一行图像的有效像素数与 SDK 分配的实际行距可能不同，零点和量化比例也直接影响框与分数。这些概念要讲清。当前缓冲绑定和解码已进入模型配套文件，核算学生要逐行手写的内容时，仍要把相应实现摊开。[历史解码实现](https://github.com/lst92991-eng/four-axis-robot-arm/blob/5d4c31bdd19602b1d8e2441a925897497508e807/vision/yolo.cpp) · [当前缓冲绑定](../models/xiangqi14-local-v3/rknn_buffers.cpp) · [当前解码](../models/xiangqi14-local-v3/postprocess.cpp)

## 下一个模块怎样照着改

1. **先选一轮学生真要完成的动作。** 例如普通走子，写出“读走法 → 求两个格点的目标角 → 取子 → 放子 → 核盘 → 记谱”。每一步旁边写它收到什么、交出什么。吃子只在取子前多一段移走对方棋子的动作。
2. **沿入口读到具体函数体。** 圈出每一个需要额外讲的状态、配置、判断和包装。固定安装一次即可取得的数据归入口；只重复描述“现在执行到哪”的状态随调用位置一起省去。裁掉一层后，再查一遍下层是否仍承担原封不动的复杂度。
3. **用一个真实后果决定保留。** 能说出“删掉后，带填充的行会读错”“横移时吸头会扫到棋子”“落子失败也会记谱”，就把处理写在能决定下一步的地方。为方便脚本限定循环次数，归测试入口。把已有检查换个名字再调用，课堂仍要付出同样的解释成本。
4. **交付可审的差异。** 给出同一函数的旧版、新版和源码位置，说清学生少维护了哪项信息、哪条业务能力仍在，再用同一批输入对照。识别比原图输入、类别、分数、位置；取放比动作顺序、目标、到位与停止；棋局比实际盘面和记谱时机。写法是否合格由代码审核确认。

用本周换肘举例，CAD 检查可以在运动前分段计算。检查用的点只有在电机确实需要停在那里时才成为运动目标。这样保留了可达性判断，也让学生能从两轴收到的最终角度理解一次横移。四段换边目前有离线直达回放，实际切换用时待实测。
