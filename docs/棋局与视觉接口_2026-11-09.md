# C++棋局、视觉与取放接口

## 2026-11-13 当前代码

这一晚已按课堂手写风格整理接口。下面“原接入记录”保留当时状态；当前源码使用Game结构体及Game_*函数，旧的 `Game::prepareRobot` 等调用名已经替换。

| 模块 | 当前调用 | 处理的数据 |
| --- | --- | --- |
| 固定棋盘 | `FixedBoard_setup`、`FixedBoard_assign`、`FixedBoard_target` | 保存90个格点XY；将每帧检测对应到格点 |
| 视觉转棋局 | `chessObservation` | 红方起算的视觉行号转换为黑方起算的棋局行号 |
| 棋局状态 | `Game_reset`、`Game_acceptHuman`、`Game_prepareRobot`、`Game_confirmRobot` | 权威盘面、待确认盘面、行棋方、起始FEN和完整历史 |
| 引擎 | `Pikafish::start`、`legalMoves`、`think`、`close` | 起始FEN加已完成历史 → 合法走法和最佳应手 |
| 运动规划 | `Arm_load`、`WorkHeights_load`、`Arm_inverse`、`Pick_plan` | 已保存机械参考、示教高度、基座XY → 关节目标和取放步骤 |
| 回合连接 | `Session_observe`、`Session_acceptHuman`、`Session_plan`、`Session_confirm` | 新观察 → 待执行动作 → 动作结果与新观察 → 已完成走法 |

运行时先设置相机/固定棋盘和已保存的机械参考，然后连续读取不同帧的观测。引擎的legalMoves与think都接收 `game.baseFen` 和 `game.history`；不能用每帧新生成的FEN替换完整对局上下文。UCI查询是同步调用，现有CAN服务继续由独立进程/线程维护。

`Session_plan`先在Game副本上验证走法，取得两个格点的已标定XY，执行逆解并生成取放步骤；所有步骤准备好后才保存pending。若吃子，则先把目标棋子搬到已示教的吃子区，再搬自己的棋子。未示教吃子区时不生成该吃子计划。这里的合法走法仍由调用方从引擎取得，库本身不重复实现完整棋规。

取放前已经处于搬运高度，J4保持原姿态。每份计划包含动作类型、J2/J3角、J1角与速度、释放脉冲时间；执行器按顺序完成。`Session_confirm`必须同时取得动作成功和新的稳定目标盘面，才写入历史。执行失败或盘面不符保留待确认状态，不自动重发动作。

当前C++模块只生成动作数据，仍未连接正式SPI-CAN执行端。已有Python实机演示保留在manual_control中；本轮没有连接机械臂。Windows构建与13组CTest通过，其中Session验证识别格点、普通搬子、吃子区、失败不提交与完成只提交一次；UCI使用实际实现加POSIX替身验证。Linux真实Pikafish进程、ARM构建及真实硬件执行仍待验证。

完整入口、当前行数及逐轮证据见[项目README](../README.md)与[本轮整理结果](项目收敛与下棋闭环_2026-11-09.md#2026-11-13-全量上层整理结果)。

## 已接上的代码边界

- `scara_chess`：9×10盘面、FEN解析/生成、UCI走法坐标、已完成走法历史、人类变化识别、机器走法准备与结果确认。真正合法走法表由引擎提供，不把`applyMove`的数据检查当作完整象棋规则。
- `scara_game_geometry`：当前视觉格点与棋局数组的行方向转换，以及引擎走法的源/目标交点到现有`PlaneMap`基座XY输出。
- `scara_pikafish`：仅Linux构建的POSIX UCI子进程接口，固定引擎目录可用`engine/pikafish-2023-03-05`。用户指定2023-03-05的ARM程序、预解压NNUE、许可与对应源码包已归档，清单在该目录。

当前视觉`row=0`在红方底线，棋局数组`row=0`在黑方底线，转换明确为`chessRow=9-visionRow`。UCI`a3a4`最终对应视觉`(0,3)→(0,4)`。没有靠屏幕上下方向猜测，未判向、混帧、unknown、非法类别或视觉冲突不会产生完整可信棋局。

先取得新鲜稳定观察，向Pikafish发送起始FEN＋完整历史，得到合法走法和应手；先验证源/目标XY、IK与路径，再用`Game::prepareRobot`锁定待执行计划。独立执行器实际完成取放后，以新的稳定观察调用`confirmRobot`。执行失败、盘面不符时历史和权威盘面不提交，也不自动重发搬运动作。

视觉连续帧稳定由现有`Stabilizer`提供，调用方仍必须检查采集会话、frame_id和时间新鲜度。该接口没有替代实际相机调度、机械执行器或CAN监督线程；UCI搜索不能阻塞电机心跳。
