# 固定棋盘的视觉、棋局与取放接口

当前是2026-11-13固定流程精简版。完整C++共1800有效行；主要入口和逐文件行数见[README](../README.md)。旧接入记录留在文末，其中类方法、动态棋盘与外部FEN解析的旧接口不代表当前代码。

## 初始化一次

- `loadPlane(path, map)`：读取新采点或保存的标定，复算映射并核对独立采点误差；相机必须匹配固定的1280×720原图配置。
- `boardFromCorners(corners, confirmed, grid)`：四角按红方视角a0、i0、i9、a9给出，确认方向后生成90个交点。
- `FixedBoard_setup(map, grid, session.layout)`：缓存90个基座XY。失败时不保留上一次坐标。
- `Arm_load`与`WorkHeights_load`：读取已保存的机械参考和实际示教Z；没有新标定或猜测丝杆导程。
- `Game_reset(game, board, redToMove, humanRed)`：从标准初局或已确认的任意盘面开始，生成起始FEN并清空历史。

只移动棋盘时重新设置四角即可；相机/基座相对位置或焦距改变时重新标定映射。修改布局后调用 `session.stable.reset()`，保留棋局历史，再获取新的稳定观测。当前不自动找格线或判断旋转朝向。

## 每回合的数据顺序

| 调用 | 输入 | 输出或状态变化 |
| --- | --- | --- |
| `Session_observe` | 新帧编号、YOLO原图检测、画面是否无遮挡 | 将身份分配到交点，三个不同有效帧一致后得到有效棋局观察 |
| `Pikafish::legalMoves(game, legal)` | 已确认Game | 引擎当前合法走法；必须先确认调用成功 |
| `Session_acceptHuman` | 稳定观察和合法走法表 | 唯一匹配的人类走法，更新已完成历史 |
| `Pikafish::think(game, timeMs, choice)` | 起始FEN与完整历史所在的Game、思考毫秒数 | 引擎应手 |
| `Session_plan` | 应手及当前合法走法表 | 查固定XY、逆解、生成取放步骤，全部就绪后保存pending |
| `Session_confirm` | 动作是否成功、已更新的稳定观察 | 新盘面等于预期才提交走法和历史；否则保留待确认状态 |

格点层和棋局层的观察都只有一个valid标志，分别表示该阶段的结果是否可用。固定XY查表与帧号无关；帧号留在识别观察里，用于拒绝重复证据。YOLO置信度仍用于0.50阈值与画框，未再复制到无消费者的格点数组。

视觉行0在红方底线，棋局数组行0在黑方底线，转换是 `chessRow = 9 - visionRow`。UCI的 `a3a4` 对应视觉 `(0,3)→(0,4)`。转换函数chessObservation就在session.cpp中，已经没有独立vision_bridge层。

Pikafish只接收由Game维护的状态，直接发送 `game.baseFen` 和 `game.history`；不再把自己的FEN反向解析一遍。FEN输出仍保留全部字段，任意初始盘面通过Game_reset设置，外部FEN文本导入不在精简版中。引擎响应的计数、格式、重复走法、部分I/O、超时、取消及回收检查保留；选中走法仍须属于合法列表。

## 取放与结束

执行前处于已示教的搬运高度，J4保持原姿态。普通取放为：保持吸持 → 源XY → 吸取Z → 搬运Z → 目标XY → 释放Z → 释放脉冲 → 搬运Z。脉冲结束后才抬升。当前是被动吸持/通电脉冲释放，H桥仍待接入。

吃子先把目标棋子搬到已示教的吃子区，再搬自己的棋子。未示教吃子区时不生成该计划。`Game_finish(game, Result::Draw/RedWon/BlackWon)`统一同意和棋与认输，正在搬子时不能结束。没有合法走法时当前方负；复杂重复局面仍转人工裁定，没有声称实现完整长将/长捉裁判。

C++模块只生成步骤，没有连接正式SPI-CAN执行端。现有Python上位机与演示保留。当前通过14组CTest和60项Python检查；UCI使用真实实现加POSIX替身，模型使用保存张量与原ONNX离线对照。真实Linux引擎、ARM构建、NPU及整机动作仍待验证。

## 已接上的代码边界

- `scara_chess`：9×10盘面、FEN解析/生成、UCI走法坐标、已完成走法历史、人类变化识别、机器走法准备与结果确认。真正合法走法表由引擎提供，不把`applyMove`的数据检查当作完整象棋规则。
- `scara_game_geometry`：当前视觉格点与棋局数组的行方向转换，以及引擎走法的源/目标交点到现有`PlaneMap`基座XY输出。
- `scara_pikafish`：仅Linux构建的POSIX UCI子进程接口，固定引擎目录可用`engine/pikafish-2023-03-05`。用户指定2023-03-05的ARM程序、预解压NNUE、许可与对应源码包已归档，清单在该目录。

当前视觉`row=0`在红方底线，棋局数组`row=0`在黑方底线，转换明确为`chessRow=9-visionRow`。UCI`a3a4`最终对应视觉`(0,3)→(0,4)`。没有靠屏幕上下方向猜测，未判向、混帧、unknown、非法类别或视觉冲突不会产生完整可信棋局。

先取得新鲜稳定观察，向Pikafish发送起始FEN＋完整历史，得到合法走法和应手；先验证源/目标XY、IK与路径，再用`Game::prepareRobot`锁定待执行计划。独立执行器实际完成取放后，以新的稳定观察调用`confirmRobot`。执行失败、盘面不符时历史和权威盘面不提交，也不自动重发搬运动作。

视觉连续帧稳定由现有`Stabilizer`提供，调用方仍必须检查采集会话、frame_id和时间新鲜度。该接口没有替代实际相机调度、机械执行器或CAN监督线程；UCI搜索不能阻塞电机心跳。
