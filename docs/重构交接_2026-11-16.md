## 给重构设备的要求

- **按教师可以顺手逐行写下来的顺序组织。** 先声明变量并交代单位，用结构体和输入／输出参数传数据。每行表达一步；不要套多层构造、在调用中藏自增，或靠新包装、搬文件、挤行数显得精简。对照原驱动的 `pid.c`、`wheel_control.c`、`motor_driver.c` 和现有相机／视觉主循环。
- **保留视觉与标定的已验证含义。** C++17、OpenCV 5.0.0；SC3336 原图 1280×720，推理 ROI `[300,70,650,600]`，RGB 640×640、letterbox、阈值与框坐标还原保持基准语义。实时预览和推理裁剪独立。棋盘固定，无 ArUco，初始化缓存 90 个点；保留首次采点、独立验误和方向确认。只用新且稳定的有效观察确认棋局。
- **保留走棋与执行的顺序。** 合法走法和应手来自 Pikafish，发送起始 FEN 与完整已确认历史；吃子先搬走目标子。取放沿用已保存机械参考与示教高度，释放脉冲结束后才抬升。实际执行完成并经新盘面确认才写历史，失败后不盲目重发。
- **保留两处硬件接入契约。** `motion/execute.hpp` 的 `Motion_execute(steps, running, success)`、`Motion_stop()` 是直接 C++ 接口。当前硬件函数明确未实现；后续 SPI-CAN／H 桥由硬件接入阶段实现，重构不再引入动作 JSON 请求或回执，不让未接硬件报成功。底层电机参数和真实标定值有自己的现场依据。
- 提交时附变更范围、读代码的入口、按同口径统计的有效行数及已跑检查。当前基点为 **2679 行自有 C++**，包括头文件、内部实现和仿真后端；测试、旧 Python 调试程序和 USB-CAN 适配另列。

## 交回后如何验收

在独立工作树检出候选提交，用现有离线夹具构建；手写风格看实际实现，行为用冻结输出逐项比对，不拿改过的夹具代替原基准。

1. 用 C++17 和此项目要求的 OpenCV **5.0.0** 构建，保留 `SCARA_WITH_RKNN=OFF` 跑离线。Windows 的 17 组 CTest 基线使用 Visual Studio 开发者终端、支持 FFmpeg 的 OpenCV 及实际版 `rknn_api.h` 编译 SDK 替身；没有此头文件时那两组测试不会进入构建。Python 3 环境需要 NumPy、OpenCV-Python、ONNX Runtime、pyusb/libusb 等既有依赖。当前 SDK、编译器和 Python 环境装在本机，路径由另一台设备按自己的安装位置填写。
2. 跑现有 CTest 和 Python 测试。重点对照 15 种完整对弈场景：正常搬运、吃子、执行失败／恢复、引擎失败、退出和重复局面裁定等。除运行编号与时间戳外，核对结果、已确认及待确认棋局、历史、每步动作类型和全部有效数值；对比的动作内容可见上面的 `program-equivalence.json`。
3. 对保存的 16 帧做 RGB、绘制和 NPU 张量离线对照，再用同哈希 ONNX 在 CPU 上核对。核对棋子类别与原图落点，不能只数检出的棋子。用 `scara_geometry_tool` 检查标定和固定 90 点的四个基准输出，并保留逆解和取放顺序检查。重复回放同一批图只证明回归一致。
4. 在候选提交上出验证记录。全部要求满足再合回联调分支。实机跟随、Linux 真实进程、RV1106 NPU 和新 SPI-CAN／H 桥另行验收；当前离线流程不会触发任何实际电机或磁铁。
