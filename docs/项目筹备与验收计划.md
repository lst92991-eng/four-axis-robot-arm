## 3. 棋盘坐标的最小方案

建议统一约定：红方视角左下交点为原点，file=0..8向右，rank=0..9朝黑方；数组为cells[rank][file]。这是一项待实现的接口约定，不是从当前画面旋转方向猜出的标定。棋盘当前红方在画面右侧，预览方向和引擎输出方向应各自显式处理。

- 图像坐标I：原始1280×720帧，u向右、v向下。截图播放器的960×540显示区域不能直接作为采集坐标。
- 棋盘坐标B：X=file×横向格距，Y=rank×纵向格距，棋盘表面Z=0，单位mm。格距未测时留空，不能用旧35/40mm稿代填。外框宽高不等于8×9格距。
- 基座坐标R：由机械实测确定，保存T_R_B（棋盘到基座）及TCP；关节角内部单位rad，设备协议的毫度只在边界换算。
- 相机内参与畸变由固定焦点、固定分辨率下多姿态标定获得。先去畸变，再用至少4个分散且非共线的已知棋盘点拟合平面映射；多点拟合，并用未参与拟合的点单独检验。
- 当前棋子遮挡边线交点：先临时清空棋盘或露出足够分散的已知交点。第一版允许人工选点，不必先做自动格线识别。
- 自动复位定位可在棋盘外围增加固定ArUco标记；其ID、边长、角点与棋盘关系必须实测，不能把标记四角直接当棋盘四角。是否增加标记不阻塞人工选点原型。
- 90点叠加要覆盖角部、中央、河界两侧，验证方向与编号；棋盘移动、焦点/机位/分辨率改变使相关标定失效。
- 平面单应性不能消除镜头畸变或棋子高度引起的视差。YOLO检测框中心用于判断归属格点，并保留离格点过远时的unknown；实际取放目标使用标定后的格点毫米坐标。若需要追踪偏离交点的棋子，应另验证顶面高度与中心定位方法。

测量模板：[90交点记录表](../config/board-points.template.csv)。先只填写真实测量和图像观测；空白不代表0，也不能把模板当已通过的全盘标定。

## 4. YOLO只接入，不训练

接收清单：文件路径及SHA-256；YOLO家族/版本；.pt/.onnx/.rknn格式；模型任务；class_id→类名顺序；输入尺寸/布局/颜色/归一化；letterbox或裁剪规则；输出张量及解码/NMS所在位置；原推理或导出脚本；模型在几张样例上的预期输出。

1. 已有RV1106适用的RKNN：先查目标芯片、转换版本和板端运行库兼容性，试单图推理；不因扩展名正确就默认可运行。
2. 只有ONNX/PT：保留原件；先复现原推理，再按真实网络确定导出和RKNN转换路径。量化如果需要，用代表当前光照/棋具/机位的样图做校准，并验证转换前后差异；不更新训练权重，不以失败为理由自动训练。
3. 不假定模型一定是YOLOv5、640×640或14类特定顺序。领域需要红黑双方各7种棋子身份；用户模型若类别体系不同，明确映射或报告缺项。
4. 空格不是默认新增的YOLO类别：只有画面覆盖有效且检测可信时才能判空；遮挡、漏检嫌疑与unknown分开。
5. 验收采用独立实拍，覆盖各类、满盘/残局、边角、反光、手部遮挡和棋子移动；分类正确不等于中心定位和90格归属正确。

已填写接入清单：[model-manifest.json](../config/model-manifest.json)；空白接收模板仍保留。当前选择直接使用用户已转换RKNN，暂不重新导出/量化。没有训练脚本、训练任务或训练环境安装计划。

## 5. 软件与板端资源准备

- Ubuntu VM承担编译、模型检查/转换、标定与可视化；Buildroot板不使用Ubuntu的apt安装方法。已验证的RTSP用于预览和前期取图，生产视觉优先接板端NV12/Rockit/V4L2，保留原帧尺度与时间戳。
- 历史目标C++17/OpenCV5.0.0只列为待核对的实现目标。本工作区没有完整SCARA应用；先接收其代码与工具链，再确定最小所需OpenCV模块，不盲目下载替换整套SDK。
- 本板为32位ARM/uClibc，不直接复制x86程序或面向glibc的通用ARM包。工具链需匹配本镜像SDK/sysroot；官方示例中的工具链路径只是参考，不能覆盖当前SDK版本。
- 系统当前可见内存170MiB，当前/userdata约232MiB可用；这不是硬件总DRAM容量。量测模型载入、帧缓冲、OpenCV和引擎内存峰值，限定队列长度，只处理必要的新鲜帧；不预先承诺30fps识别。
- 已有NPU库和模块文件不等于推理验收完成。先记录运行库/驱动/模型版本，再做加载、单图、连续推理和内存检查；不为匹配未知模型先升级运行库。
- **当前内核明确CONFIG_CAN未启用。** SocketCAN/can0不能直接使用。先评估将已验Candlelight 2.5用户态USB传输移到RV1106（需libusb、USB Host与权限）；若改走SocketCAN，则需匹配内核配置、gs_usb与FD/BRS兼容性并重新构建验收。现在不重刷内核。
- SW5切换会影响Type-C ADB。换到USB Host前先建立并验证eth0管理通路；不把usb0当持久管理通道。适配器始终由一个控制会话持有。
- 搜索/视觉可串行安排以控制内存，但不能阻塞电机的500ms有效命令超时监督；后续采用有界、可取消的调用或独立监督路径。时效参数在实测后填写。
- 捕获时间、主机接收时间和板端毫秒计数注明clock_domain；RTSP接收时间不伪装成传感器曝光时间。未校准时序的画面不用作运动EKF观测。

## 6. 最小接口草案

| 输出 | 必要字段 | 无效时如何处理 |
| --- | --- | --- |
| Frame | frame_id、width/height、pixel_format、capture/receive时间及clock_domain、camera_config_id | 无帧/过期/格式不符不推进识别 |
| Detection | frame_id、model_hash、class_id、score、原始帧坐标下bbox/center、预处理变换 | 不明class_id、反变换失败或低置信标unknown |
| BoardObservation | frame_id、calibration_id、90格piece/empty/unknown、稳定性、遮挡、整体valid | 未标定、重复占格、遮挡或未停稳不提交棋局 |

| PickPlaceResult | task_id、已完成步骤、驱动反馈、复拍结果、故障原因 | 指令ACK/线圈通电不等于棋子搬运成功 |
