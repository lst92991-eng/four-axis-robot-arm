# 三点几何与三轴联动阅读说明（2026-11-17）

## 几何主线

输入只保留一个3×4 double点表，三行固定为a0、i0、a9，各列为u、v、X毫米、Y毫米。对应的逻辑行列是(0,0)、(8,0)、(0,9)。初始化依次读取三点、解像素到基座的系数、解像素到行列的系数、生成90点。Geometry_init共21有效行，核心两文件140行。已移除独立检查集、凸包、重复采点排查和四角重复输入；教材说明选点和固定机位，现场通过叠图和取放检查效果。

## 联动主线

用户明确J4不动。AxisValues的三个元素依次是J1电机角、J2反馈角、J3电机角；沿用原机械参考与减速换算。

1. `Pick_plan`生成完整三轴目标。吸取后先到clearance层，下一段同时继续上抬至travel层并移动J2/J3。释放脉冲结束后再离开。未额外示教clearance时沿用travel层。
2. `Trajectory_plan`根据每轴位移、速度和加速度限幅求公共时长T。
3. `Trajectory_sample`按共同进度`s=10u³-15u⁴+6u⁵`生成三轴位置与速度，`u=t/T`。起止速度和加速度为0。该插补位于关节空间，末端路径由关节运动决定。
4. `Motion_execute`从新反馈建立起点，同周期交付三轴参考，等所有轴实际到位并连续停稳250ms才进入下一段。取消、参考发送失败、反馈中断和到位超时都会请求整组减速保持；停止未确认时明确报错。
5. `Drive_read/write/release/stop`分别负责新周期反馈、三轴参考下发、定时释放和整组停稳确认。真实函数目前未连接；仿真在链接时提供这四个函数，执行的是同一个Motion_execute。

运动六文件共388有效行，包含头文件和未接硬件的端口。速度与加速度限幅在game配置中各是一组三个数；J4不在参考数组中。不要把仿真夹具的clearance或限幅当作现场参数。

## 验证和硬件边界

14组Linux CTest通过，包含15个完整对弈场景、三轴共同进度、速度/加速度限制、末端精确参考、整组取消/故障收尾和释放脉冲顺序。没有连接或操作真实机械臂。

现有v3 MOVE只允许停稳后接受整段目标，不能直接用于这里的周期参考。上机前还需实现相应参考命令和SPI-CAN收发，接入device.cpp；H桥也需真实接入。当前软件测试证明规划和调度逻辑，不能替代板端或机械验收。旧Python手动路径没有在本轮改成联动。
