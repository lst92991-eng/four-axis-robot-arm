## 打开与启动

Windows 本机浏览器打开 **http://127.0.0.1:8090/**。程序运行在连接 USB-CAN 的 Windows 上，这个地址不是 Ubuntu 虚拟机里的 localhost。当前版本仅监听本机，不开放局域网控制。

项目根目录 PowerShell：

```powershell
& ./manual_control/start.ps1
```

仅测试界面、完全不访问 USB 的模拟模式：

```powershell
& ./manual_control/start.ps1 -Simulate -Port 8091
```

界面角落明确区分“真实硬件”和“模拟测试 · 不连接电机”。启动只接收状态，点击“允许手动点动”才开始序号握手；不会自动设零、清故障、出力或移动。退出服务用原终端 Ctrl+C。

## 操作

- 四轴各有正转、反转按钮及独立速度输入。范围 0.1～30°/s，默认 1°/s；新速度在下一次按下时生效。J2 使用输出轴单位，25:1 减速换算已经由固件完成。
- 按住鼠标左键或触控按钮运动，松开、移出按钮、指针取消、窗口失焦时请求 STOP，减速后保持位置。长按最多到达软件行程边界，不会越过边界无限转圈。
- 一次只操作一个轴。“全轴停止”、空格、Esc 停止当前控制，停稳后可以再次按方向按钮；不会自动续动。
- “结束手动控制”取消控制会话；浏览器消失、控制进程退出或通信中断均不会自动恢复运动。
- J1 为升降轴，当前 °/s 是电机转速，不是 mm/s。丝杆每转位移尚未在本次验证，未生成毫米读数。
- 角度只有在驱动报告参考有效且反馈新鲜时显示。未参考时显示“—”，不把 STATUS 中的默认 0 当成真实位置。
- 调试记录可以展开查看；原始收发、序号、接受/拒绝、停止确认写入 `output/manual-control/*-real.jsonl` 或 `*-sim.jsonl`，不混淆模拟与真实证据。

## 与当前固件的对应

使用已验证的 Candlelight 2.5 / WeActStudioV1 适配器，序列号 `37813482333551062`，500k/2M CAN FD/BRS。复用 `temp/transport/stepfoc_candlelight.py` 与 USB 独占机制，不修改驱动或适配器固件。

| 项目 | 实现 |
| --- | --- |
| 控制协议 | v3，64 字节，小端，命令 ID `0x400+node`，ACK `0x480+node`，状态 `0x200+node` |
| 按住 | 单次 MOVE，目标为该方向已审阅的软件边界；主机按 100 ms 周期 PING 续看门狗 |
| 松手 | STOP；看实际状态到 HOLD 且 stationary，或 OFF 且 power=false，才显示停止确认 |
| 不重发运动 | MOVE 的 ACK 丢失/拒绝后停止，不把重试当作新运动 |
| 页面心跳 | 80 ms；主机租约 300 ms，过期 STOP 并停止 PING |
| 状态及 ACK | 250 ms 超时；真实时序取决于主机调度与 USB 延迟 |
| 驱动后备 | 原固件 500 ms 无有效命令后减速保持并锁定；不是瞬时制动 |
| 正常停止 | 不发 OFF，避免 Z 轴失去保持力；本次不提供断出力、设零或清故障按钮 |
| 序号同步 | STATUS 不携带最近命令序号，仅用 PING 探测 uint32 序号空间，不用 ZERO/OFF 同步 |
| 同时操作 | 单页面控制所有权、每次按压 ID、递增操作序号；晚到的开始请求不能越过较新的停止请求 |

原固件在通信失联后会设置 `interlocked`；这个页面不绕过锁定，也不会自动用 OFF/ZERO 清锁。确实失联后，要另行处理驱动状态与机械参考。仅按“全轴停止”且页面仍正常工作时继续 PING 保持，不会人为制造失联锁定。

主机边界来自已烧录固件配置：各轴目前为 -180～180°，**不是已经测量过的真实机械行程**。尤其 J1 只覆盖一圈；需要扩大升降行程时应同时修订固件行程及主机已核对配置，不能只把网页数字放大。未知构建 ID 不会沿用旧行程。

上位机使用 Python 标准库 HTTP 服务和现有 USB 传输层，浏览器原生 HTML/JS；C++17/OpenCV 5.0.0 几何模块、视觉 ROI、NPU 模型及磁铁 GPIO 均未改动。

这四个构建的 `CONFIG_ENCODER_ZERO=-1`；`Motor_initialize()` 因而将 `motor_configured` 设为 false，`handleMove()` 调用 `Motor_canRun()` 会拒绝运动。这是当前固件本身的条件，不是上位机额外要求重新验证六轴运动能力。用户所述物理参考有效与驱动当前 `referenced=false` 分别记录，不推断物理参考丢失。

当前上位机已具备控制流程，但**真实电机运动尚未由这个页面验收**。需要取得已验证的电角标定方法/各板参数，更新配置并核对构建 ID，然后在真实驱动中建立对应机械参考。不能将四轴电角零点随意写为同一个数字，也不能仅删除 `motor_configured` 判断。
