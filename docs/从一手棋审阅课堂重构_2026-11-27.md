# 从主程序读一手棋 · 旧新代码对照

旧版固定为 `987860c`，新版是这次工作区中的 C++。先审 `MatchSession::playTurn`，在定义处搜索 `//---------走一手棋---------`。在本机也可以直接看 [所有生产 C++ 的逐行差异](../output/teaching-review-20261127/teaching-cpp.diff) 或 [旧版完整主流程](../output/teaching-review-20261127/before/app/game.cpp)。版本库中可复现同一个旧版。[对局源码](../app/game.cpp) · [远端基线](https://github.com/lst92991-eng/four-axis-robot-arm/blob/987860c3bf7a9d0aeea57c0f127bfd8127870d88/app/game.cpp) · [十二条课堂规范](课堂代码写作规范.md#逐行手写的十二条规范)

## 先顺读一次正常对局

1. `main → Site_loadFile → RV1106_configure → Match_run`。读完安装表后，RV1106 取得模型路径、相机裁剪、棋力引擎设置和运动限幅。对局收到本机配置和棋局状态。台架与仿真在各自的入口交付已重放的棋局。缺模型路径返回 2，读表失败在启动处报告并返回 1。[入口](../app/game_main.cpp) · [安装数据](../app/site.cpp)
2. `MatchSession::start → parkForObservation → readBoard`。启动先准备观察位，再用三张连续有效的新帧确认实盘。操作者确认开局后再看一次，确认期间有人挪棋时会重新核盘。续局要和已有棋谱的盘面吻合。[开局](../app/game.cpp) · [观察](../app/game.cpp)
3. `MatchSession::playTurn → selectMove`。在选棋时查引擎、核对合法表并判断是否终局。引擎拿起始 FEN 和完整棋谱，交付本回合的合法表，轮到电脑时同时给出应手。[回合](../app/game.cpp) · [皮卡鱼](../chess/pikafish.cpp)
4. 玩家在面板选棋和电脑应手共用机械执行路径。玩家亲手移动时，`selectMove → readBoard → inferMove` 从实盘识别这一步，随后直接走到共同的记谱位置。
5. 开局从安装表为 90 个格点一次算好关节目标。机械搬棋先用 `waitForOriginal` 核实原盘，按行列查目标，再用 `Plan_turn` 排好整手动作。吃子先把对方棋子送到盘外弃子位，再搬己方棋子。[动作计划](../motion/plan.cpp)
6. `confirmLanding → Game_commit`。实盘到达预期局面才更新棋盘、轮次和棋谱。操作者恢复原盘时沿用已排好的动作重走；退出保留最后确认的棋谱。驱动执行失败另走处理设备、确认停车、返回观察位、核对原盘的路径。

## 四处可以直接对照的源码

### ① 面板和电脑怎样共用一手棋

旧版在两个不同层次启动机械臂。下面是两处独立的真实调用。

```cpp
if (!carryMove(staticParams, dynamicParams, move)) return;
```

```cpp
return carryMove(staticParams, dynamicParams, move);
```

第一处在电脑回合，第二处藏在玩家选棋函数里。后者返回成功有时表示“相机看到了玩家手走”，有时已完成整手搬运。新版选棋交付走法以及手走、代走或结束操作的结果，两种需要机械臂的走法都经过 `playTurn` 的同一处。

```cpp
if (!readBoard(&match.game.board) || !waitForOriginal()) return;
std::vector<PickStep> steps;
planMove(move, steps);
if (!executeAndConfirm(move, steps)) return;
```

棋盘的逆解在开局完成。`planMove` 根据 `move` 查关节目标并处理弃子位，输出本手完整计划。执行与视觉恢复沿用这份动作表。[旧版](https://github.com/lst92991-eng/four-axis-robot-arm/blob/987860c3bf7a9d0aeea57c0f127bfd8127870d88/app/game.cpp#L103) · [新版](../app/game.cpp)

### ② 从相机盘面看出玩家走了哪一步

旧版对合法表中的**每个候选**都做一次试走。

```cpp
Board trial = before;
movePiece(trial, step);
if (trial != seen) continue;
```

新版从实际变化出发。一遍扫完 90 格，记下变空的源格和变成另一枚棋子的落点，再执行如下核验。

```cpp
if (observed.fromRow < 0 || observed.toRow < 0) return false;
char piece = before[observed.fromRow][observed.fromCol];
if (piece != seen[observed.toRow][observed.toCol]) return false;
if (countMove(legal, observed) != 1) return false;
move = observed;
```

合法表有 L 项，旧版至多做 L 次整盘复制和比较；新版扫描一次棋盘，再查一次合法表。吃子时目标格可以从对方棋子变成刚从源格离开的己方棋子。第二个离开格、第二个到达格、错子或重复候选都不能记谱。上游仍核对当前行棋方、源格和被吃棋子。[旧版](https://github.com/lst92991-eng/four-axis-robot-arm/blob/987860c3bf7a9d0aeea57c0f127bfd8127870d88/chess/board.cpp) · [新版](../chess/board.cpp)

### ③ 按动作表执行到下一步

旧版通过 `size_t completed` 取 `steps[completed]`，再维护 `bool ok`，成功时增加计数，循环结束又比较 `completed == steps.size()`。新版在 `runSteps` 直接写 `for (const PickStep &step : steps)`。成功到位后，就在当前动作更新三轴保持角。

```cpp
if (!moveAxes(held, target, limits, running, feedback)) return false;
held = target;
```

`moveAxes` 分成按时间发送运动参考、发一次零速终点、读取新反馈等停稳。只有终点下发后到来的反馈可以确认该目标。自审时也删除了中间稿的 `targetSent` 标志，执行到哪个循环已能表达这件事。吸附等待期间的保持、取消、超时和关磁铁停车都保留在相应的设备边界。[旧版](https://github.com/lst92991-eng/four-axis-robot-arm/blob/987860c3bf7a9d0aeea57c0f127bfd8127870d88/motion/execute.cpp) · [新版](../motion/execute.cpp)

### ④ 看清引擎到底做了哪两笔问答

旧版的公共入口写 `openEngine(directory) && io.query(game, thinkMs, legal, best)`，要进入 `Uci::query` 才能看到是查合法表还是搜索应手。新版先组合一次含完整历史的 `position` 命令，再进行两笔问答。

```cpp
bool ok = io.open(directory) && io.legalMoves(position, legal);
if (ok && !legal.empty() && game.redToMove != game.humanRed)
    ok = io.bestMove(thinkMs, best);
```

打开引擎包含握手。一次查询的 FEN 与历史共用一处换行检查。每笔问答拥有自己的回复格式，最后回收子进程，失败清空未完成的结果。学生可以先写明两笔问答，再下钻看短写、分行和回收。[旧版](https://github.com/lst92991-eng/four-axis-robot-arm/blob/987860c3bf7a9d0aeea57c0f127bfd8127870d88/chess/pikafish.cpp) · [新版](../chess/pikafish.cpp)

## 其余函数的取舍

| 顺着代码读 | 改动或保留依据 |
| --- | --- |
| `readJoint / readArm / readHeights / readSite` | 三个示教点按红左、红右、黑左分别读到变量，再交给标定。单位、带符号传动比例、有效工作层和旧安装迁移检查仍在读表处。取放函数接收数值。 |
| `Geometry_calibrate / Geometry_gridPoint / findSquare / Geometry_assign / Geometry_draw` | 删除与 `cell[0][0]` 重复保存的 `origin`。标定时直接用实测黑左，像素归格和毫米弃子检查都从同一表取原点。行列步长、偏格拒绝、同格冲突和独立预览仍有直接用途。 |
| `Vision_observe / inferPieces` | Windows C++ 台架里，帧号、张量格式、内存范围和数据包寿命归入真正执行板端推理的 `inferPieces`，由它返回棋子列表。读帧、裁剪、识别、绘图的正常顺序可以直接看见。这处是把协议细节放到接口边界，协议工作量仍计入台架。[台架视觉](../bench/field/usb_io.cpp) |
| `Match_run / waitReady / Operator_prepare` | RV1106 的开局确认和玩家输入由扩展板按钮接入。按钮接入前，开局确认会报告设备尚未接入。台架在入口打开设备会话，在自身的命令接口解析面板文字。 |
| `initialBoard / Game_reset / validBoard / validTransfer` | 删掉第二份十行开局字符串和逐行复制，按摆棋的次序写空盘、两条底线、炮、隔列兵卒。保留九宫、棋子身份和数量、两方颜色与盘内下标检查。 |
| `sameMove / countMove / parseMove / uci / startFen` | 删除自定义相等运算符。四个行列值由同一处比较，面板和相机共用合法表唯一性检查。解析直接填写输出，失败复位；四字符 UCI 在协议边界产生。 |
| `Game_commit / Game_replay / Game_judge` | 记谱和轮次只在落子已确认后更新。重放已有棋谱、同一方重复局面转人工裁定均有独立作用。 |
| `Plan_turn / Plan_pick / Plan_place / Plan_move` | 开局把 90 格与已示教弃子点换算为关节目标。取放规划按实际吸放次序组织，普通走子 9 步、吃子 15 步。 |
| `Arm_forward / Arm_inverse / Trajectory_plan / Trajectory_sample` | 两连杆逆解展开小臂沿大臂及垂向的投影。采样写明五次多项式的三次幂和各轴带符号行程。共同的运动时间、速度与加速度约束均有物理含义。 |
| `gripPiece / Motion_stop / stopOutputs` | 吸住后维持原姿态再抬升。关磁铁和停车各自都要尝试；任一个失败都不能报告已安全收尾。 |
| `MatchSession::readBoard / confirmLanding` | 读盘按顺序取新帧、归格、确认三帧。落点核对区分落子确认、摆回原盘或退出。所有发动作的路径在 `executeMotion` 使旧盘面失效。 |
| `restorePark / parkForObservation / Runtime_close` | 故障恢复先处理实际棋子、清空吸头、确认停稳，再回观察位。走子中断后须核对原盘。原生 RV1106 的底层驱动接口待接入，Windows USB-CAN 使用独立设备后端。 |

## app 层整改复审

- 安装入口在生成格点前拒绝像素或基座平面退化的三点。在交给动作规划前检查 J1 抬升方向和工作层顺序。RV1106 和 Windows 实机入口都要求本机安装表。
- 观察器按递增帧号接收新帧。原盘、目标盘、重走和记谱由对局处理。发出机械动作前清除旧观察的确认标志。手走偏差直接用已取得的盘面报告。
- 两套接入共用弃子侧归格，盘内偏位仍需核对。普通取放和吃子先垂直抬到搬运全高再横移。回观察位的执行失败进入同一恢复流程，确认停稳后才重试。
- 对照 31 个既有场景，退出码、棋局结果、棋谱、确认盘面、J2/J3 目标和吸放一致。动作数值差异为取放后从旧净空层改抬到搬运全高。补做三点退化、反向 Z、重复帧、旧盘面失效、弃子侧和回位报错的离线验证。
| 相机、YOLO、RKNN 与工具 | 已认可的相机、YOLO、RKNN 核心作为对照样板。RV1106 在对局中取帧核盘，Windows 台架把预览画面交给面板。示教、旧安装导入和仿真有各自入口。 |

## 对照结果

- 以 `987860c` 源码独立编译旧版，新版重新构建。相同 28 个对局场景逐项比较退出码、标准输出和标准错误，全部一致。对照覆盖 61 次调用、435 条动作，含普通走子、吃子、人工修正落点、恢复原盘、取消和设备异常。[逐场景摘要](evidence/2026-11-27/teaching-cpp-review.json)
- 11,959 个手走识别对照、48,600 个棋格起终点组合、14,400 个几何归格用例的新旧结果相同。98 组运动学、2,000 组轨迹采样和 23 个执行场景另外比对了角度、速度和驱动事件序列。
- 新版在 Windows 通过全部 14 个 CTest 和 11 项台架离线回归。相同输入下，20 号的 361 条规划动作和 21 号的 723 条规划动作与改前逐条一致；视觉回放通过 16 帧、152 项保存检测。硬件联调和本次离线验收分别记录。
- 明确计数范围为 `app/chess/motion/vision` 的 25 个 CPP 与头文件。排除空行和纯注释、计入花括号，改前 1,688 行，改后 1,739 行。另计实际使用的 Windows C++ 桥接文件 312 → 316。此轮总行数增加，集中在把开局、棋盘差分、错误出口与动作执行写成可手敲的步骤。可直接核查的删减是整盘试走复制、重复开局字符串、走法运算符、引擎转发、完成计数和重复黑左原点。
