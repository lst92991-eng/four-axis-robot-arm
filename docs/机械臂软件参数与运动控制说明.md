## 1. 先采用的方案

- 棋具先固定一种：直径35mm的32枚棋子，厚度约10～15mm，交点间距40mm。实物到手后记录实测值；尺寸是项目选择，不是已经测过的商品参数。
- 相机镜头放在棋盘中心正上方，光轴垂直棋盘。用户后续明确采用全3D打印支架：新设计默认镜头前端距底脚安装面646.4mm，用50mm增高件分档调高；实际距棋盘还要扣除棋盘表面的高差，并按实拍校准。
- 四轴先完成单位、方向、回零、限位、反馈与停止。运动平顺优先使用驱动器已有的加减速/轨迹缓冲能力；能力不足再做主机轨迹时间规划。
- 背隙先测量。只有误差显著且方向规律稳定时，才增加定向接近或有限速度的背隙补偿。
- EKF按用户明确的目标用于运动状态估计。现有棋盘单应矩阵EKF不算运动EKF，也不能证明机械减振。
- 复用现有主循环、规划器、模拟器和统一测试入口，不为了四个节点引入通用设备框架或插件体系。

### 3.1 坐标与正逆解

当前[运动学接口](../algorithm/fk.hpp)约定：基座肩轴中心为XY原点，从+Z向下看逆时针为正，长度用mm、角度用rad，Z向上。`q1`相对基座，`q2`相对第一臂，`q4`相对第二臂。

```text
x   = L1*cos(q1) + L2*cos(q1+q2)
y   = L1*sin(q1) + L2*sin(q1+q2)
yaw = q1 + q2 + q4
q4  = 目标yaw - q1 - q2
```

这些公式以工具中心在腕轴中心为前提。实际TCP若有平面偏置或高度偏置，需加入工具变换，不能只改Z。末端保持同一朝向时，腕轴通常需要随前两轴补偿旋转。四角棋盘定位得到的平面映射，也不等于已经取得棋盘到机械臂基座的变换。

### 3.3 电机单位到关节单位

若协议位置`m`是**电机轴计数**，这条数据每电机转对应计数为`N`，基础换算为：

```text
q = q0 + sign * (m-m0) * 2*pi / (N*i)
Z = z0 + sign * (m-m0) * lead / (N*iZ)   // lead单位mm/丝杆转
```

指令计数与反馈计数可能使用不同尺度，应分别记录`Ncmd`与`Nfeedback`，不能默认共用一个`N`。Z轴先用`iZ`得到丝杆转数，再乘导程。

仅当驱动器的协议单位及缩放**已经包含机械传动比**时，应用层才不再重复换算。设置电子齿轮本身不证明包含了减速器；需核对具体映射。毫米、角度、整数计数只在驱动边界转换；FK/IK与规划内部继续用mm/rad。

J1反装可解释为：在同一物理正方向下，常规减速关系是`输出相对壳体角=电机相对壳体角/i`；输出固定后，`壳体角=-电机相对壳体角/i`。这解释了结构负号，但最终`sign`还取决于电机安装朝向及反馈极性，不能未经核对直接设为-1。

| 抓手和负载质量/惯量 | 尚无可靠整机质量惯量 | 最快工况验证需确认，可用材料可靠的CAD估算或称重，不是给定轨迹计时的先决条件 |
| 吸牢、释放、落子后停稳时间 | 没有本抓手/棋子的有效实测值 | 需要在实际抓手、棋子、管路和运动参数下测试；初算仅能给等待假设 |
| 满载可用速度/加速度、跟随误差、振动 | 空载宣传转速和静态标称转矩不能替代 | 判断最快且可靠的完成时间需要实测验证；未验证时只给条件化理论值 |
| 通信、到位回报及主机调度延迟 | 可先按链路和协议预算，不含真实USB/Linux调度波动 | 要逼近实际总时间时测量；理论轨迹时间应单列这些开销 |

所以不需要先把所有参数实测一遍。J1速比已确认50；第一轮理论指令时间优先补Z导程，确认J2齿数及固件类型，然后明确速度/加减速、合法起终点路径、抬升距离、取放等待和是否回等待位。实际可靠时间再用负载运动、抓取释放和停稳测试校正。此处仅明确资料缺口与验证方法，未授权或执行硬件动作。

### 3.6 2026-10-09 走棋分项计时：20mm抬升方案

J1实际减速比已由用户最终确认 **50∶1（输入∶输出）**，本节可以据此计算给定运动参数下的轨迹时间。下面三档是计算假设，不是额定能力、实机推荐参数或已经测出的最快/最慢边界；所有动作采用静止起步、静止结束的对称梯形/三角形加减速，未计jerk限制。

| 假设档位 | J1电机速度/加减速 | J1、J2关节速度/加减速 | Z线速度/加减速 |
|---|---|---|---|
| 较慢 | 300rpm / 600rpm/s | 36°/s / 72°/s² | 20mm/s / 80mm/s² |
| 中档 | 600rpm / 1200rpm/s | 72°/s / 144°/s² | 40mm/s / 160mm/s² |
| 较快 | 900rpm / 1800rpm/s | 108°/s / 216°/s² | 60mm/s / 240mm/s² |

J1换算为 `关节速度(°/s)=电机rpm*6/50`。J2暂用相同的关节速度/加速度，按名义3∶1分别相当于电机18/36/54rpm、36/72/108rpm/s；实际齿数确认后再换算。Z导程尚未给出，因此只假设线速度，不将它冒充已实现的电机转速；若导程为p mm/转，中档40mm/s对应电机转速为 `2400/p rpm`（直接驱动假设）。本计算采用物理加速度；若实际使用Emm档位，需换算并按可用档位重算。

用户要求将运动与思考时间分开，并将抬升由原50mm改为20mm。本节按**从抓取接触位置向上移动20mm**重算；它不是距棋盘绝对高度20mm，也不是比其他棋子顶面再高20mm。实际净空仍需结合最高棋子、工具长度/包络及误差核对。

其他明确假设：吸取等待0.5秒、释放0.3秒，每次完整取放再预留通信/停稳合计0.2秒；R保持相对第二臂的当前姿态，不额外把棋子文字转正。参考等待点W=(0,440)mm，弃子点C=(270,210)mm，均为计算用点，不是已标定或推荐的实物位置。

不吃子的机械计时边界是：W通行高度出发→源点上方→下降/吸取/抬升→目标上方→下降/释放/抬升→返回W静止。共3段水平运动、4次20mm升降、1秒等待预算。吃子先从目标点移走对方棋子到C，再移动己方棋子，最后回W，共5段水平运动、8次20mm升降、2秒等待预算。机械执行时间不包含视觉、引擎思考、回零和异常重试。

对位移s、最大速度v、加速度幅值a：`T=2*sqrt(s/a)`（s≤v²/a）；否则 `T=s/v+v/a`。水平段让两轴共享归一化进度曲线，以最大关节位移控制耗时，避免只同步终点却改变路径。保持同一肘分支，离线每不超过0.5°检查关节路径是否位于既有4°CAD矩阵中四角均通过的单元；此筛查不替代新的连续碰撞计算、落子高度及工具/棋子净空验证。

| 机械执行示例（源→目标，mm；含吸放与等待） | 较慢假设 | 中档假设 | 较快假设 |
|---|---:|---:|---:|
| 相邻交点40mm：(20,256)→(-20,256) | 11.85s | 7.57s | 6.12s |
| 沿棋盘200mm：(-100,296)→(100,296) | 11.69s | 7.60s | 6.22s |

| 横跨360mm且先移走目标棋子到C | 20.17s | 13.27s | 10.89s |

不同示例源点距等待点不同，因此不能只按棋子搬运直线距离比较总时间。J1单独转90°在中档假设下为1.75秒，不能用90/72=1.25秒遗漏加减速。中档Z轴每次20mm运动为 `20/40+40/160=0.75s`，包含加减速。

### 5.3 用视场角估算高度

设要完整覆盖的“棋盘＋标记白边”外包络长宽为`W、H`，对应画面水平/垂直角为`alpha、beta`。每个方向最多使用画面80%，留出安装和定位余量，则近似：

```text
h >= max[ W / (0.8 * 2*tan(alpha/2)), H / (0.8 * 2*tan(beta/2)) ]
```

这是近似针孔计算，角度单位需一致；最终仍以该镜头实际图像验证。[视场角与工作距离关系](https://docs.baslerweb.com/knowledge/angle-of-view-calculation-in-the-basler-lens-selector)。

以原480×520mm标记板为例，把520mm方向对齐画面长边，需要水平视场至少650mm、垂直视场至少600mm。4:3画面若垂直覆盖600mm，水平方向对应约800mm。

| 假设的有效垂直视场角 | 覆盖600mm垂直范围所需高度 |
|---|---:|
| 40° | 824mm |
| 45° | 724mm |
| 50° | 643mm |
| 55° | 576mm |
| 60° | 520mm |

表中角度是演算例子，不是这颗MIS5001镜头的实测值。650mm起点大致对应有效垂直视场约50°时的需求。

### 5.4 不知道焦距，也能用一帧图确定高度

1. 先让镜头垂直朝下，把尺子或已知尺寸的纸放在**棋盘上表面所在平面**，量当前镜头到该平面的高度`h0`。粗装时用镜头前端量距，随后正式标定修正光心偏置。
2. 沿图像横、纵方向分别取一段已知长度`Lx、Ly`，测它们在原始1280×960图中的像素长度`px、py`。不要用浏览器缩放后截图的显示像素代替原图像素。
3. 近似全画面覆盖宽高：`Fx0=1280*Lx/px`，`Fy0=960*Ly/py`。
4. 所需高度：`h_new=h0*max(W/(0.8*Fx0), H/(0.8*Fy0))`。调整后再拍照验证四个标记的完整白边与所有棋子均在画面内。

例：高度500mm时，100mm尺段占原图200px，近似全画面为640×480mm。对于横520/纵480mm的目标外包络，留上述余量后，估算高度为625mm。**200px是计算示例，不是本次实拍数据。**

该方法要求同一镜头、对焦与采集裁剪不变，并尽量用画面中部尺段。广角畸变明显时先标定/去畸变，再测比例；四角单应变换本身不能消除径向畸变。

### 5.5 看得全还要看得清

若有效视场约800×600mm，1280×960原图中35mm棋子直径约56px，48mm标记黑框约77px。这只是分辨率预算；字形细节、失焦、压缩和反光仍会影响识别。不要通过无限抬高相机来避免遮挡。

固定漫射照明，避免棋面高光；对焦在棋子文字附近，并检查四角标记同样清楚。保存实际曝光时间、增益、白平衡和帧率。需要锁定曝光/白平衡时，以现场光照实测为准，不预先填一个万能值。

更换镜头、对焦距离、分辨率、裁剪或支架位置后，重新验证标定。检测耗时约85ms是本项目NPU测试的单次检测口径，不包含采集与传输，不能把该视觉链路当作高频电机控制环。

### 5.6 棋子高度带来的定位偏差

四角标记校正的是棋盘平面，棋子文字在更高的平面。对正上方针孔相机，棋子中心距光轴在棋盘上的投影点为`r`，棋子厚度为`t`，相机距棋盘为`h`，把棋子顶面直接映射到棋盘平面会产生近似径向误差：

```text
偏差 = r*t/(h-t)
```

例：棋盘网格角点`r≈241mm`、棋子厚12mm、相机高650mm，偏差约4.5mm。它是高度视差，不是减速器背隙，也不应靠EKF把真实偏差“平滑掉”。

对落子识别，使用检测结果判断所属交点；对取放目标，优先使用**已标定的交点机械坐标**。若要抓取明显偏离交点的实物棋子，需考虑棋子高度、内外参及实际抓取中心，再做修正。当前12mm的视觉交点归属容差不是允许12mm的机械定位误差。

## 6. 背隙会不会造成抖动

**会在某些工况下造成或加重抖动，但有背隙不等于每次运动都持续振荡。** 典型表现是：换向时电机先走一段而负载没动，另一侧齿面重新接触后发生冲击；位置控制器反复跨越空程，也可能来回修正。参见[Beckhoff机械背隙说明](https://infosys.beckhoff.com/content/1033/backlash/15312602251.html)与[MathWorks齿面接触/分离建模](https://www.mathworks.com/help/sm/ug/backlash-joint-limits.html)。

| 现象 | 优先排查 | 对应方法 |
|---|---|---|
| 同一点从两个方向接近，最终位置不同 | 减速器/丝杆/联接处空程 | 测换向差；定向接近或经验证的背隙补偿 |
| 加速、急停时晃动，停下后衰减 | 结构柔性、惯量、轨迹冲击 | 紧固/支撑、降低加速度和jerk、平滑轨迹 |
| 某个速度/频率特别容易振动 | 电机/机械共振、控制环参数 | 驱动参数整定，测频率后才考虑陷波 |
| 负载或伸展姿态变化后偏移变化 | 刚度、挠曲、工具偏置 | 负载/姿态测量、结构改进，不能只补一个常数 |
| 静止时读数抖，但实物未见移动 | 测量噪声、量化、时间戳 | 检查测量；适量滤波与状态估计 |
| 停机/重启后坐标突然不一致 | 丢步、未回零、编码器回绕/零偏错误 | 恢复定位与反馈检查，不用滤波掩盖 |

对同轴TCP，小角度误差可近似估算：`末端XY误差上界≈(L1+L2)*abs(δq1)+L2*abs(δq2)`，角度用rad。若仅J1有0.1°输出误差，最伸展处约0.82mm；若仅J2有0.1°，约0.48mm。**这是敏感度例子，不是本减速器已测背隙值。** Z轴空程直接表现为高度误差；腕轴空程主要影响朝向，工具偏心后也会引入位置误差。

## 7. 解决策略：按实测问题逐层增加

### 7.1 第一层：结构、参数与轨迹

1. 先处理松动、孔轴配合、联轴器、同步带张力和支架刚度。张力/预紧按零件允许值设置，不能靠无限拉紧消除误差。
2. 核对每轴方向、零点、单位和传动比。J1反装负号、J2相对角和Z导程错误不是“抖动参数”。
3. 优先使用驱动器现成的加减速、S曲线和同步启动/轨迹缓冲功能；只有驱动能力不足时才在主机补时间规划。[S曲线与jerk取舍](https://www.rockwellautomation.com/en-pl/docs/studio-5000-logix-designer/38-02/contents-ditamap/instruction-set/drives-instructions/tune-an-s-curve-profile.html)。
4. 当前`PlanStep`约1mm是路径采样点。平滑必须覆盖一整段连续动作，不能让每个采样点都零速起停。对有拐角的路径，需要明确减速到位或可接受的过渡误差，并重新检查整条扫掠路径。
5. 四轴需要共同的时间基准。逐个发目标并让四个驱动各自“尽快到位”，不能保证协调的TCP轨迹；确认驱动器是否支持同步触发、带时间戳目标或缓冲轨迹。

### 7.2 第二层：测量后再补偿背隙

可先用低速、空载及典型负载做往返定位测量：在同一姿态和同一目标，分别从正反方向接近，等待相同的稳定条件后，用输出侧测量比较位置。覆盖近/中/远几个姿态并重复若干次，记录换向差、离散程度和负载依赖。单次偏差不直接当作背隙常数。

简单选项是“从同一关节方向完成最后接近”，但为了绕行到同侧而新增的路径仍需限位/碰撞检查。TCP从同一方向靠近，不必然意味着两个转动关节都从同一方向靠近，要按最终关节轨迹判断。

软件换向补偿需要保存最后有效运动方向、实际输出侧空程和补偿完成状态；复位、故障或手动挪动后应重新建立状态。补偿应平滑分配在有限时间内，继续遵守速度、加速度、jerk与限位；不要在换向瞬间突然多发一大段角度。厂家说明也指出瞬时补偿会激励机器，需要时应分摊到多个控制周期。[补偿动态效应](https://infosys.beckhoff.com/content/1033/backlash/15312602251.html)。

若驱动器已启用背隙补偿，主机不能再重复补偿。目标到位后的有限等待可以帮助振动衰减，但不能消除静态空程，也不能替代实际到位/吸附反馈。

### 7.3 第三层：运动反馈与EKF

用户希望EKF服务于机械臂运动。可以从`x=[q1,q2,z,q4,dq1,dq2,dz,dq4]`的8状态开始，但先明确每项测量从哪里来。

- 仅使用匀速状态模型与编码器直接读关节角度时，模型是线性的，普通KF足够。
- 融合真实末端标记的视觉位置/姿态时，FK及相机投影形成非线性观测，才有使用EKF的具体理由。需保存相机标定、标记到TCP变换、编码器/图像时间戳、测量延迟和噪声估计。[EKF适用条件](https://www.mathworks.com/help/fusion/ug/extended-kalman-filters.html)。
- 静态棋盘四角只能测相机与棋盘的关系，不能测机械臂实际运动。当前只测XY时也无法完整观测Z和同轴腕角；需要相应的编码器或姿态/深度测量。
- 电机侧编码器位于减速器之前时，不能直接测到减速器之后的全部空程和弹性偏差。负载侧编码器或末端观测可用于验证实际输出位置；不能拿“命令已经发出”代替反馈。
- EKF提供状态估计，控制器依据估计误差产生控制量。大幅真实振动不能当成噪声直接滤掉；过度滤波或错误延迟处理会影响控制响应。

第一版不预建双惯量辨识、MPC或自适应控制框架。若驱动板已实现快速电流/速度环，先利用其能力，RV1106负责视觉、规划、指令协调与状态监督；普通Linux用户态和USB-CAN链路不作为未经验证的硬实时伺服环。

| 6 平滑 | 比较相同运动的原方案与平滑方案 | 速度/加速度限制检查、稳定时间、真实末端轨迹；不只看动画 |
| 7 补偿/估计 | 只有对应问题显著时启用补偿；按运动教学目标验证EKF | 原始反馈、估计值、独立真值/检查量、时间戳与延迟 |
| 8 整局 | 取子、吃子、收纳、遮挡、停止/恢复均能复核 | 执行前后盘面、工具状态、确认时刻和失败恢复记录 |

定位精度、稳定时间和可接受抓取偏心尚未验收。可先把“交点位置误差不超过2mm”作为讨论/测量目标，但它不是已达到的精度，也不是根据未知吸盘尺寸得出的保证；最终允许误差由实物棋具、吸盘有效接触区和抓取试验共同确定。

## 11. 后续实现约束

主流程仍按“观察→合法走法→规划→执行→复核→提交”顺序展开。硬件变化集中在参数、相机/驱动边界，运动学保持清晰单位。每增加一项优化，先证明它改善了对应实测问题，再保留代码；不为了演示算法名称同时堆叠滤波器。

当前[`homography_ekf`](../algorithm/homography_ekf.hpp)估计的是棋盘映射。后续运动EKF应有明确独立的关节状态与真实测量；视觉定位是否还需要原EKF，按固定支架后的测量结果决定。先完成本参数表，再修改算法与驱动，不把CAD尚未确认的数值静默写入运行程序。
